# OCMOD Rules

## Головне правило

Усі зміни, виконані в межах оптимізації WheelDecalsHub, повинні зберігатися після оновлення модифікаторів OCMOD (OCMOD Refresh).

## Правила роботи

1. Перед зміною файлу визначити його походження та перевірити, чи не генерується або не модифікується він через OCMOD.
2. Не вносити критичні для оптимізації зміни лише в кешовані або згенеровані OCMOD-файли.
3. Якщо файл контролюється модифікатором, зміни повинні вноситися у вихідний файл, відповідний OCMOD-модифікатор або інше джерело, з якого результат може бути відтворений після OCMOD Refresh.
4. Перед кожною зміною зберігати резервну копію оригіналу та фіксувати, що саме змінюється.
5. Не виконувати широкі або глобальні заміни без попередньої перевірки точного збігу та кількості входжень.
6. Якщо очікувана структура файлу, збіг або кількість входжень не відповідає перевіреному стану — зупинитися і спочатку з’ясувати причину.
7. Після змін перевіряти функціональність сайту та показники сторінки, якої вони стосуються.
8. Для змін, які можуть залежати від OCMOD, фінальна перевірка повинна включати OCMOD Refresh і повторну перевірку того, що оптимізація не втрачена.
9. Усі суттєві зміни та спосіб їх збереження після OCMOD Refresh документувати в CHANGELOG.md.

## Принцип

OCMOD Refresh не повинен скасовувати, перезаписувати або робити неактивним жодне оптимізаційне рішення, яке є частиною фінального результату проєкту.
